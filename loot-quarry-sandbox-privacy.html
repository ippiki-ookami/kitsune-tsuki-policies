1. What this notice covers

This notice describes preparation for a private, operator-only evaluation of Loot Quarry's eBay Sandbox connector. It does not cover a production connection, public store or checkout, advertising, or access by additional users.

The first proposed connected phase is limited to verification of the Sandbox test seller's identity and one account-privilege read, with the necessary owner consent and token handling. A separate minimal identity-discovery read may precede verification if needed. The proposed phase uses no native application database and includes no order intake, reconciliation, listing changes or quantity operations. Those later activities require their own review and authorization.

A narrow identity/read and cleanup helper has entered local source authoring. It has not been qualified for use or verified in connected operation. The descriptions below separate wider reviewed software capabilities from that first-phase candidate. Publishing a notice does not authorize a connection or transaction.

Use authorized Sandbox test accounts and synthetic test content. Confidential, personal or restricted information must not be published in Sandbox listings or test content. Account identifiers and any additional information returned by the provider still need private handling. These are operating restrictions, not a claim that an automatic filter enforces them.

2. Information the connector can handle

If separately authorized, the connector can handle application credentials, access and refresh credentials, consent scope and state, and seller identifiers used to check the intended account. Sign-in and permission approval take place through eBay. The reviewed connector does not store an eBay account password.

The first proposed phase would keep only minimal private seller-identity evidence and bounded status/count results. The privilege response would be checked in memory rather than saved as a raw body or retained privilege fields. These are requirements for the helper under local source authoring, not verified safeguards.

Responses from eBay can contain additional personal fields in memory. In the wider reviewed connector, saved order evidence selects references, dates, amounts, statuses, quantities and related operational facts; separate native order and audit records also exist. Those order operations are outside the first phase. Excluding buyer, address and message fields from one format does not make every record anonymous or mean personal information is never received.

An optional diagnostic probe can save raw response bodies, and optional request logs can contain identifiers in paths or query fields. The first proposed phase excludes raw-body probes and response-body logging. The actual route and complete output inventory must be verified before connected use.

3. Purposes and recipients

The first proposed phase is limited to authorized test-seller identity verification and one account-privilege read. Later order intake, reconciliation, offer or quantity testing is separate. No unrelated advertising, sale of data or marketing use is authorized.

The connector communicates with eBay and is intended to run on the operator's reviewed devices and private storage. The exact first-phase access list, storage locations and copy/backup boundaries still require verification. Additional recipients, processors, countries or uses require review before introduction.

The notice host is separate from the private application. Only specifically approved informational release files would be uploaded; application credentials, private identity evidence, orders and other application data are excluded.

4. Storage and security

The reviewed credential store writes permission-protected plaintext files; it does not itself encrypt them. Device, disk and backup encryption have not been verified. Tokens can remain in process memory, and no secure memory-erasure guarantee is established.

The reviewed transport verifies HTTPS certificates. This and application access checks do not establish that every device, log or backup meets all security requirements.

Before a connected synthetic phase, Software must verify the actual private credential/output locations, operator access and separation from real authority records and shared backup/export paths. The DB-free helper has entered local source authoring; its exact output/cleanup controls still require completed implementation, independent review and synthetic qualification. Production security and incident-process qualification remains separate.

5. Retention and cleanup

No fixed retention duration has been approved for this evaluation. The wider reviewed native history is immutable and has no demonstrated expiry, account-erasure or anonymization mechanism. Diagnostic files, logs, screenshots and recovery copies lack a verified end-to-end cleanup process. Native history is outside the proposed DB-free first phase; its limitations are not silently cured by that proposal.

The proposed first-phase alternative uses segregated, disposable test storage, no writes to real authority records, no raw-body probes and no unreviewed backup/export copies. Before connected use, identify every retained output and verify a workable, authorized end-of-purpose cleanup method and the applicable end-of-testing application disposition. Local artifact cleanup, browser/clipboard remnants and provider consent/application/test-account disposition are separate outcomes.

Only an agreed sanitized completion receipt would be retained, without provider content, account identifiers or hashes derived from identity/credential-bearing files. No retention period for that receipt is invented here.

This is a proposed minimum, not evidence that an isolated mode or cleanup operation is qualified or operational. If the selected route cannot isolate and retire its outputs, that connected phase remains unready. Unexpected real personal data requires stopping before durable persistence and controlled handling. Ordinary file deletion is not secure erasure and does not prove removal from provider systems, browser storage, snapshots or other copies. Interrupted or incomplete cleanup must remain recorded as partial.

Applicable rights and contractual duties remain even when an erasure tool is absent. Real-personal-data retirement and the production notification/valid-opt-out requirements need their own applicable review before the relevant use. They are not blanket prerequisites for disconnected fixtures or a suitably reviewed isolated synthetic phase. No automatic deletion, universal exemption or fixed erasure time is promised.

6. Authorization and privacy requests

The selected contact for this notice and privacy matters is legal@kitsune-tsuki.com, with the founder-reported linkage and verification limits stated above. Do not send passwords, authorization codes, tokens, identity documents or customer records in ordinary privacy correspondence.

The existing business-mail route assigns the exact legal/privacy matter to Legal & Company Records. Legal identifies the relevant data owner, who supplies an authorized handling proposal and result. This is manual handling, not automatic erasure or authority for an agent to send replies, access accounts or change records. A valid request must not be disregarded because an erasure tool is absent.

Withdrawing permission through eBay and cleaning local credentials or data are different actions. The reviewed source handles expired or rejected authorization; that does not establish automatic provider revocation or removal of every stored credential or historical copy.

7. Hosting of this information page

The selected destination for this standalone information page is a dedicated informational GitHub Pages project site. GitHub documents security logging of visitors' IP addresses. Its general privacy statement describes service-dependent usage/device/request data and cookies, processing in several countries including the United States, and retention based on purpose and legal obligations: https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement . These general disclosures do not establish this eventual page's exact cookie set, log-retention duration or processing region. No page-specific runtime or cookie/header measurement is asserted here.

This three-file informational release set contains no forms, client-side scripts, analytics, embedded widgets or automatically loaded external fonts/images. This finding applies only to those exact files. Any regenerated release files need the same check. It does not describe every hosting-provider process, and no wider cookie-free, tracking-free or no-personal-data promise is made.

This site is solely an information page, not an application, store, checkout or commercial service. Public release content and commit metadata may be copied or retained by others; later unpublishing cannot guarantee removal of those copies.
